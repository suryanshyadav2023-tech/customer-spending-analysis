# Customer Spending Behavior Analysis in E-Commerce

Predicts, for each user of the REES46 multi-category store, whether they will buy in the last week of
October 2019 (`will_purchase`) and how much they will spend (`future_spend`). Features come only from
Oct 1-24 (RFM plus clickstream behaviour); targets come only from Oct 25-31.

The pipeline:

- segments users with K-means;
- compares three feature sets: (a) RFM, (b) RFM + behavioral, (c) RFM + behavioral + segment;
- compares single-stage models with a hurdle model, P(buy) x E[spend | buy];
- audits a deliberately leaky setup;
- explains the Random Forest classifier with SHAP.

Everything runs on CPU with scikit-learn and pandas. Results are in [RESULTS.md](RESULTS.md) and the report package
is in [outputs/report/](outputs/report/).

## Get the dataset

Only `2019-Oct.csv` from the Kaggle dataset
[mkechinov/ecommerce-behavior-data-from-multi-category-store](https://www.kaggle.com/datasets/mkechinov/ecommerce-behavior-data-from-multi-category-store)
is used. It must end up at `data/raw/2019-Oct.csv` (5,668,612,855 bytes).

Option 1, kagglehub. This worked without a Kaggle login for this public dataset; a `~/.kaggle/kaggle.json` also works:

```bash
python -c "import kagglehub; kagglehub.dataset_download('mkechinov/ecommerce-behavior-data-from-multi-category-store', path='2019-Oct.csv', output_dir='data/raw')"
```

The download is a 1.61 GB zip archive saved under the name `2019-Oct.csv`. Rename it and extract it:

```bash
mv data/raw/2019-Oct.csv data/raw/2019-Oct.csv.zip
python -c "import zipfile; zipfile.ZipFile('data/raw/2019-Oct.csv.zip').extractall('data/raw')"
```

Option 2: download `2019-Oct.csv` from the Kaggle page and place it in `data/raw/`.

## Reproduce everything

```bash
python -m pip install -r requirements.txt

python run_all.py              # reuses data/processed/sample.parquet (skips step 01)
python run_all.py --resample   # rebuilds the 10% user sample from data/raw/2019-Oct.csv first
```

All steps use seed 42 and are deterministic. Random Forest predictions can differ between runs in the last floating-point
digits (trees are summed across threads). Step 09 fails the run if the saved models do not reproduce the
test metrics.

Measured runtimes on the development machine (16 logical CPUs, Windows 11):

| Run | Time | Source |
|---|---|---|
| `01_sample.py` (only with `--resample`) | 83 s | `data/processed/run_all.log` |
| `python run_all.py`, steps 02-08 | 348 s | `data/processed/run_all_final.log` |
| `python run_all.py`, steps 02-09, machine busy with other work | 773 s | `data/processed/run_all_r3.log`, `outputs/tables/runtime.csv` |

## Launch the demo

```bash
streamlit run app.py
```

If `streamlit` is not on PATH (on this machine it is installed under the user Scripts folder), use
`python -m streamlit run app.py`. The demo reads only `models/`, `data/processed/` and `outputs/`; nothing is
retrained. It has three pages:

- **Overview:** T1, the architecture diagram, the feature-set comparison, hurdle vs single-stage, and the leakage audit.
- **Customer:** User A/B/C from the worked example, or any test user by test-set index. Shows features, segment,
  stage-1 probability, stage-2 estimate, hurdle prediction, actual spend and a SHAP waterfall.
- **Segments:** T5, the naming rule, and the per-segment top SHAP features (T6).

Headless check of all pages:

```bash
python tests/test_app.py
```

## Rebuild the report template

`outputs/report/report_template.docx` has section headings with `[WRITE: ...]` placeholders, tables T1-T6, figures with
numbered captions, and equations. It is built from the files in `outputs/report/` by a Node script (docx 9.7.2):

```bash
cd tools/report_template
npm install
node build.js
```

## Saved models

`models/manifest.json` lists every file, its feature columns and how it was chosen. The demo uses the
`final` entry: the hurdle on feature set (c). Its stage 1 is `rf_clf_c_rfm_behav_cluster.joblib`, and its stage 2 is
`hurdle_stage2_c_rfm_behav_cluster.joblib`. Its segments come from `segmentation.joblib`. The single-stage
comparison uses `rf_reg_c_rfm_behav_cluster.joblib`. The Random Forest classifier and regressor for every feature
set are saved, plus the Logistic Regression stage 1 used by the (a) hurdle.
