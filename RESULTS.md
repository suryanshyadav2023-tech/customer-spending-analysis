## Caveats

- `remove_from_cart` has 0 events in the 10% user sample (event types were not counted in the full file), so n_remove_from_cart is constant 0 and was dropped from all models.
- K = 3 came from the default rule, not from agreement: elbow K = 4, best silhouette K = 2.
- K sensitivity: conclusions that differ from K=3: K=2: Segments found; K=2: An 'Engaged browsers' segment exists; K=4: (c) minus (b) test ROC-AUC, LogisticRegression [95% CI].
- Tuned thresholds are high (0.8190 to 0.8836) because class_weight='balanced' inflates probabilities (mean raw P = 0.3349 vs test purchase rate 0.0250 for (b) RFM + behavioral); the hurdle uses prior-corrected probabilities.
- Random Forest (c) vs (b): tuned F1 0.2582 vs 0.2445 (thresholds 0.8275 vs 0.8578), while ROC-AUC is 0.7955 vs 0.7973. The F1 gap comes from the operating point, not from better ranking.
- Decision Tree (b) and (c) have the same tuned threshold (0.8836) and identical test precision/recall/F1 at it (tuned-F1 difference +0.0000, CI [+0.0000, +0.0000]), although their ROC-AUC differs.
- (c) vs (b) ROC-AUC is small for every classifier (largest |difference| = 0.0036); RF validation ranks (c) first, RF test ranks (b) RFM + behavioral first.
- future_spend is heavy-tailed; RMSE/R2 are driven by a few users. Top-10 test users = 62.1% of Linear Regression (a) squared error and 49.8% for Random Forest (b). Linear Regression max prediction 28,426 for a test user with obs-window monetary 174,449.35 (largest in test: 174,449.35) whose actual future_spend is 0.00.
- Per-segment SHAP: segment indicators are constant within a segment; their SHAP values reflect the gap to the global baseline (second ranking excludes them).
- 3,050 sampled users bought in Oct 25-31 without any Oct 1-24 event; they are outside the population by design.
- Data quirks kept as-is: 3,217 exact duplicate rows in the sample; 646 users with mean session duration > 24 h.
- Hyperparameters are fixed (not tuned); one month, one split. Bootstrap CIs cover test-set sampling only, not training variance. Timestamps are UTC.
