# Methods facts

Generated by `src/07_report.py` from code constants and pipeline outputs.

## Data
- File: `data/raw/2019-Oct.csv` from Kaggle dataset `mkechinov/ecommerce-behavior-data-from-multi-category-store` (only the October file). Size: 5,668,612,855 bytes (5.67 GB).
- Raw events: 42,448,764; raw users: 3,022,290. Event counts in the 10% user sample: view 4,058,093, cart 92,978, purchase 73,828, remove_from_cart 0 (event types were counted in the sample only, not in the full file).
- Columns read: event_time, event_type, product_id, category_id, price, user_id, user_session (category_code and brand not read). Timestamps are UTC.

## Sampling
- pandas read_csv in chunks of 5,000,000 rows; keep users with user_id % 10 == 0.
- Result: 4,224,899 events, 301,732 users (0.0998 of users). Saved to data/processed/sample.parquet.
- user_session UUIDs converted to 64-bit integers with pandas.util.hash_array (deterministic).
- Exact duplicate rows kept as-is: 3,217 in the sample.

## Windows, population, targets
- Observation (feature) window: [2019-10-01 00:00:00, 2019-10-25 00:00:00) UTC. Prediction (target) window: [2019-10-25 00:00:00, 2019-11-01 00:00:00) UTC. Reference time for recency and days_since_last_event: 2019-10-25 00:00:00 UTC.
- Population: users with >= 1 event in the observation window: 255,577.
- will_purchase = 1 if the user has >= 1 purchase event in the prediction window; future_spend = sum of price over those purchase events (0 otherwise).
- Assertion in code: every feature event is before the reference time (no target-window data in features).

## Features (observation window only)
- `recency_days` (RFM): days from the user's last purchase to 2019-10-25 00:00 UTC; 60 if no purchase.
- `has_purchased` (RFM): 1 if the user made >= 1 purchase in the window, else 0.
- `frequency` (RFM): number of purchase events.
- `monetary` (RFM): sum of price over purchase events.
- `n_sessions` (behavioral): number of distinct user_session ids.
- `n_views` (behavioral): number of view events.
- `n_carts` (behavioral): number of cart (add-to-cart) events.
- `n_remove_from_cart` (behavioral): number of remove_from_cart events (DROPPED, see below).
- `avg_session_duration` (behavioral): mean over the user's sessions of (last event time - first event time), in minutes.
- `cart_to_view_ratio` (behavioral): n_carts / n_views (0 if n_views = 0).
- `purchase_to_cart_ratio` (behavioral): frequency / n_carts (0 if n_carts = 0).
- `days_active` (behavioral): number of distinct calendar days (UTC) with >= 1 event.
- `n_categories` (behavioral): number of distinct category_id values among view events.
- `days_since_last_event` (behavioral): days from the user's last event of any type to 2019-10-25 00:00 UTC.
- remove_from_cart: the sample (301,732 users) contains 0 remove_from_cart events, so n_remove_from_cart is 0 for every user; columns with a single value on train are dropped automatically (common.feature_sets), so it is in no model.
- Recency cap: 60 days for users without a purchase (observation window is 24 days), together with the has_purchased flag.
- Feature sets: (a) 4 features ['recency_days', 'has_purchased', 'frequency', 'monetary']; (b) 13 features; (c) = (b) + one-hot segment indicators (one column per K-means segment).

## Split
- Outer split: train 204,461 / test 51,116 (test_size=0.2), stratified on will_purchase, random_state=42.
- Inner validation: 20% of train, stratified, random_state=42: inner train 163,568, validation 40,893. Used only for choosing the hurdle stage-1 classifier, the Random Forest explained by SHAP, and F1 thresholds.
- Scalers are fit on train only (inside sklearn Pipelines); K-means scaler and centroids are fit on train only.

## Segmentation
- Inputs: the (b) features, log1p transform, StandardScaler (fit on train).
- KMeans(n_init=10, random_state=42); K tried 2..8; silhouette on a 20,000-user train sample (random_state=42); elbow = K with the largest distance below the chord of normalised inertia.
- Decision rule: use K if elbow and silhouette agree, else K=3. Result: ambiguous (elbow=4, silhouette=2) -> default K=3.
- Naming: rule in outputs/report/cluster_naming.md (buyer if >= 0.5 of train users purchased in Oct 1-24; non-buyers split by mean views and sessions vs train means). Target-window data not used.
- K sensitivity: feature set (c) and segment profiles rerun with K=2 and K=4 (outputs/tables/k_sensitivity_*.csv).

## Models and hyperparameters (scikit-learn; fixed, not tuned)
- Classifier LogisticRegression: StandardScaler -> LogisticRegression(class_weight='balanced', C=1.0, l1_ratio=0.0, solver='lbfgs', max_iter=5000, fit_intercept=True, random_state=None)

- Hurdle stage 2: RandomForestRegressor(n_estimators=200, max_depth=12, min_samples_leaf=20, min_samples_split=2, max_features=1.0, criterion='squared_error', bootstrap=True, random_state=42), trained on 5,103 train users with future_spend > 0.

## Hurdle model
- predicted_spend = P(purchase) x E[spend | purchase].
- Stage 1 classifier per feature set = highest validation ROC-AUC: (a) RFM: LogisticRegression; (b) RFM + behavioral: RandomForest; (c) RFM + behavioral + segment: RandomForest.
- Probability correction (undo class_weight='balanced'): odds = p/(1-p) x n1/n0, p_corrected = odds/(1+odds), with train positives n1 = 5,103 and negatives n0 = 199,358 (n1/n0 = 0.025597).

## Evaluation
- Classification metrics on test: accuracy, precision, recall, F1 at threshold 0.5 and at the tuned threshold, ROC-AUC, PR-AUC (average precision).
- Threshold tuning: for each classifier x feature set, the threshold maximising F1 on the validation split (model fit on inner train; sklearn precision_recall_curve, predict positive if p >= threshold); applied unchanged to the test predictions of the model fit on all of train.
- Regression metrics on test: MAE, RMSE, R², on all test users and on test buyers only.
- Bootstrap: 500 paired resamples of the test users with replacement (numpy default_rng(42)); 95% CI = 2.5th and 97.5th percentiles; buyers-only intervals use the buyers inside each resample.
- Leakage audit (deliberately flawed): features rebuilt from [2019-10-01, 2019-11-01) with reference time 2019-11-01; same users, targets, split, models; K-means refit on those features with the same K.
- SHAP: shap.TreeExplainer (default settings) on the Random Forest classifier with the highest validation ROC-AUC; 2,000 random test users (random_state=42); per segment up to 1,000 test users.
